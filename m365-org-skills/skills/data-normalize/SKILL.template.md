# 名簿・顧客データの正規化と重複検出 (data-normalize)

## 目的

名簿の表記を機械的な規則でそろえ、何をどう変えたかを 1 セルずつ記録して返す。重複は「候補」として示し、統合や削除は利用者が判断する。値を推測で補ったり、勝手に行を消したりしない。

## 前提

- スクリプトのサンドボックスはインターネットにも社内ネットワークにも接続できない。住所の正誤や郵便番号の実在確認はできない (形式をそろえるだけ)。扱えるのは添付ファイルだけ。
- 個人情報を含むので、回答に全件を書き写さない。表示は要約と、変更例・要確認・重複候補に限る。
- 列ごとの規則は列名から自動で決まる (メール→email、電話/TEL/FAX→phone、郵便/〒→postal、フリガナ/カナ→katakana、その他→文字の整形)。決め方は `resources/normalize-rules.json`。

## 手順

1. **ファイルを探す**: `python3 scripts/locate_inputs.py --ext .csv,.tsv,.txt,.xlsx,.xlsm` を実行する。見つからない (終了コード 1) ときは、名簿ファイルを添付するよう頼んで止まる。
2. **実行**: `python3 scripts/data_normalize.py <ファイル>`
   - Excel で複数シートなら `--sheet <シート名>`。
   - 規則を変えたい列があれば `--rule "列名=規則"` (規則: text / katakana / hiragana / phone / postal / email / nfkc / none)。例: 「備考はそのまま」→ `--rule "備考=none"`。
   - 重複の判定列を指定されたら `--dup-key "氏名+電話番号"` (複数指定可)。指定がなければ規則ファイルの組み合わせのうち、表に存在するものと「全列一致」を使う。
3. **出力を読む**: 標準出力の Markdown に、列ごとの規則・変更件数・要確認・重複候補が出る。出力ファイルは 3 つ: `<元の名前>_normalized.csv` (整えたデータ、列と行の並びは元のまま)、`<元の名前>_changes.csv` (変更ログ)、`<元の名前>_duplicates.csv` (重複候補)。

## 回答の形

- 日本語で、まず結論 (例: 「500 行中 213 セルを整形、要確認 6 件、重複候補 4 組」)。
- スクリプトの「列ごとの規則と件数」の表と、要確認・重複候補の表を貼る。
- 3 つの CSV をダウンロード用ファイルとして返す (UTF-8 BOM 付き、Excel でそのまま開ける)。
- 前提を書く: 使ったファイルとシート、列ごとの規則、重複の判定キー、行番号は元ファイルの行番号であること、メールアドレスは全体を小文字にしたこと。
- 「要確認」は自動で直していない。理由 (先頭の 0 の欠落の疑い、桁数違い、市外局番の区切り不明など) を添えて、利用者の確認を促す。

## エラー時

- `エラー: ...` (終了コード 2) は利用者が直せる問題。内容をそのまま伝え、対処を案内する。
- 文字コードを判定できない: Excel で「CSV UTF-8」として保存し直すか、`--encoding cp932` を試す。
- 列が見つからない: 表示された列一覧から正しい列名を選び直す。
- 電話番号や郵便番号が Excel の数値として保存され、先頭の 0 が落ちている場合がある。要確認に出るので、元データを文字列として保存し直すよう案内する。
