# 表記・体裁チェック

## 目的

社内文書を `resources/style-rules.json`(〇〇社の表記ルール。管理者が編集できる)に照らして機械的にチェックし、指摘一覧と修正案をユーザーに返す。**意味・数字・固有名詞は変えない**。

## 入力

- チェックしたい文書:.docx / .txt / .md(添付)、またはチャットに貼り付けた文章
- 任意:重視する観点(例:「表記ゆれだけ」「文体の統一を重点的に」)

## 手順

1. **入力を探す**:`python3 scripts/locate_inputs.py --ext .docx,.txt,.md` で添付ファイルのパスを確認する。
   - 文章がチャットに貼り付けられている場合は、その本文を `input.txt`(UTF-8)に保存して対象にする。
   - 何もない → 「チェックする文書(.docx / .txt)を添付するか、本文を貼り付けてください」と依頼して止まる。
   - .doc / .pdf / .pptx など → 「この形式はチェックできません。Word の .docx か .txt で保存して添付してください」と伝える。
2. **チェックを実行する**:
   `python3 scripts/style_check.py <パス> --out style-report.md --csv style-report.csv`
   - 終了コード 2 はエラー。表示されたメッセージをそのままユーザーに伝える(ルールファイルの誤りもここで出る)。
   - .docx の「行」は段落番号(空の段落も数える)。ユーザーには「該当箇所」の文字列で探すよう案内する。
3. **結果を説明する**:`style-report.md` を読み、次の順でまとめる。
   1. 件数の要約(種別ごとの件数)
   2. 優先して直すべき指摘(括弧の対応、文体の混在、禁止語、二重否定)
   3. 指摘一覧の表(行:位置 / 種別 / 該当箇所 / 提案)。50件を超える場合は主要なものに絞り、全件は CSV にあると伝える。
   - スクリプトは機械的に判定しているため、誤検出がありうる(例:引用文、固有名詞・製品名の表記、「及ぶ」の活用)。明らかな誤検出は「対応不要」と明記する。
4. **修正版を提案する**(ユーザーが希望した場合、または指摘が少なく修正が明らかな場合):
   - 指摘箇所だけを直した全文を示す。変更した箇所が分かるよう、変更前→変更後の対応表も付ける。
   - 文の意味、数値・日付・金額、人名・社名・製品名、引用部分は変えない。長い文の分割や言い換えは、意味が変わらない範囲にとどめる。
   - 判断が必要な箇所(どちらの文体に統一するか等)は、修正せずにユーザーに確認する。

## 出力

- チャット:日本語で、要約 → 重要な指摘 → 指摘一覧の順に示す。
- ファイル:`style-report.md`(指摘一覧)と `style-report.csv`(Excel で開ける UTF-8 BOM 付き)を返す。修正版を作った場合は `revised.txt` も返す。ユーザーが Word を希望した場合は、エージェント自身の文書作成機能で修正版の Word 文書を作る。

## ルールの変更について

チェック内容は `resources/style-rules.json` で決まる(表記ゆれ辞書、冗長表現、禁止語、文の長さの上限、各チェックの有効・無効)。ユーザーから「このルールは不要」と言われた場合はその回答の中で該当指摘を除外して説明し、恒久的な変更は管理者にルールファイルの更新を依頼するよう案内する。
