# 議事録作成

## 目的

会議の文字起こし・メモから、社内でそのまま回覧できる議事録の下書きを作る。**文字起こしにない決定事項・担当者・期限・数字を作らない**ことが最優先。

## 入力

- Teams の文字起こしファイル(.vtt、または Word でダウンロードした .docx)
- 会議メモのテキスト(.txt / .md、またはチャットに貼り付けた文章)
- 任意:会議名、日時、参加者、配布先など、ユーザーが補足した情報

## 手順

1. **入力を探す**:`python3 scripts/locate_inputs.py --ext .vtt,.docx,.txt,.md` を実行して添付ファイルのパスを確認する。
   - 見つからず、チャットにも本文がない → 「Teams の文字起こし(.vtt か .docx)を添付するか、メモを貼り付けてください」と依頼して止まる。
   - 複数見つかった → どれを使うか確認する(新しい順に表示される)。
2. **文字起こしを整形する**(ファイルが添付されている場合。チャットに貼り付けたメモだけなら手順 3 へ):
   `python3 scripts/transcript_to_text.py <パス> --out transcript.txt`
   - 終了コード 0:同じ話者の連続発言をまとめた `[HH:MM:SS] 話者: 発言` 形式と、会議時間・話者別の発言割合が出る。以降は `transcript.txt` を読む(元ファイルより小さい)。
   - `[HH:MM:SS]` は**録音開始からの経過時間**で、会議の実時刻ではない(`[00:12:34]` は「開始から 12 分 34 秒」)。
   - 「警告:」で始まる行が出たら、その行が指す箇所(本文として扱った見出しに似た行、本文のない見出し、発言として扱わなかった冒頭の行)を `transcript.txt` と照らし、話者の割り当てがおかしければ議事録でその箇所に「(話者要確認)」を付ける。冒頭の行に会議の日付があれば、日時の欄に使ってよい。
   - 終了コード 3 で「話者と時刻を含む文字起こし形式ではありません」と出たら(.txt / .md / .docx のどれでも同じ)、文字起こしではなく会議メモである。`transcript.txt` に本文がそのまま書き出されているので、それをふつうの会議メモとして読み、手順 3 に進む(会議時間・発言割合の統計はない)。
   - 終了コード 2(未対応の形式、文字コード不明、空のファイルなど)は、エラーの内容をユーザーに伝え、.vtt / .docx / .txt(UTF-8)での添付を依頼して止まる。
3. **テンプレートに沿ってまとめる**:`resources/minutes-template.md` の見出し構成で書く。
   - 日時:ユーザーの補足か、ファイル内の記載(.docx 冒頭の日付など)からだけ取る。分からなければ「要確認」。`[HH:MM:SS]` の経過時間や統計の「会議時間」の開始〜終了から日時・開始時刻・終了時刻を作らない(録音の長さとして「(録音 約45分)」と添えるのはよい)。
   - 場所・形式、欠席者、記録者:文字起こしからは分からないので、ユーザーの補足がなければ「要確認」。
   - 参加者:文字起こしに登場した話者を列挙し、「(発言のなかった参加者は要確認)」と添える。所属は文字起こしに出てこないので、ユーザーの補足がなければ書かない。
   - 決定事項:「〜で決定」「〜でいきましょう」「異議なし」など、**合意が明確な発言だけ**。根拠の時刻と話者を書く。
   - ToDo:表形式(No. / 内容 / 担当 / 期限 / 根拠となる発言)。担当・期限が発言で明示されていなければ「要確認」と書き、推測で埋めない。「来週まで」など相対的な期限は発言どおりに書き、日付に換算するのは会議日が分かるときだけ。
   - 要約:先頭の 3 行(結論・最大の決定・次の行動)。本文を書き終えてから書く。
   - チケット候補:ToDo のうち作業として切り出せるもの。技術的な決定(採用する方式・変更する設定値・見送った案)は決定事項に含める。見送った案の理由は、発言で述べられていればそのとおりに書き、述べられていなければ「理由:要確認」と書く(理由を推測で補わない)。
   - 保留事項:結論が出なかった論点、「持ち帰り」「次回検討」とされたもの。
   - 次回:発言があれば記載、なければ「要確認」。
   - 議事内容は要旨にまとめ、言い回しの細部や雑談は省く。固有名詞・数字・金額は文字起こしのとおりに書く。聞き取りが怪しい箇所(文脈に合わない語)は「(聞き取り要確認)」を付ける。
4. **見直す**:決定事項・ToDo の各行に根拠となる発言があるかを確認し、根拠のない行は削除するか「要確認」に直す。

## 出力

- 議事録を Markdown ファイルとして保存し、ダウンロードできる形で返す。これがこのスキルの主な成果物で、依頼が「要約して」だけでも作る。
  - ファイル名: `議事録_YYYYMMDD_<会議名>.md`。会議日が分からなければ `YYYYMMDD` を `日付要確認` に、会議名が分からなければ `会議` にする。ファイル名に使えない文字(`/ \ : * ? " < > |`)は `_` に置き換える。
  - ユーザーが `.txt` を希望すれば同じ内容を `.txt` で返す。
- チャットには、冒頭に「文字起こしから作成した下書きです。要確認の箇所を確認してください」と一文添え、**要約の 3 行と ToDo の表だけ**を表示する(本文全体は貼らない。ファイルで渡す)。
- ユーザーが Word を希望した場合は、エージェント自身の文書作成機能で同じ内容の Word 文書を作る(スクリプトでは作らない)。
- 最後に「要確認」の件数と、その一覧(どの項目か)を短く示す。

## してはいけないこと

- 文字起こしにない決定・担当者・期限・数字を補うこと。もっともらしい推測も書かない。
- 発言者を取り違えること。話者が「(話者不明)」の発言を特定の人に割り当てない。
- 個人の評価や感情的な発言を議事録に残すこと(業務上必要な事実だけを書く)。
