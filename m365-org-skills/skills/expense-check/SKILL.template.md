# 経費・請求データのルールチェック (expense-check)

## 目的
経費・請求の明細を `resources/rules.json` のルールで 1 行ずつ確認し、どの行がどのルールに当たるかを正確に示す。判定はスクリプトに任せ、AI の推測で違反を足したり消したりしない。最終判断は担当者が行うものとして、指摘は「確認候補」として伝える。

## 前提
- スクリプトのサンドボックスはインターネットにも社内ネットワークにも接続できない。扱えるのは添付ファイルだけ。経費システムや共有フォルダは見に行けないので、明細を CSV か Excel で書き出して添付してもらう。
- ルールの中身 (上限額・禁止語・期限・列名の対応) は `resources/rules.json`、意味は `resources/rules-guide.md`。利用者が自社用のルールファイル (.json) を添付したら、そちらを `--rules` で使う。

## 手順
1. **ファイルを探す**: `python3 scripts/locate_inputs.py --ext .csv,.tsv,.txt,.xlsx,.xlsm,.json` を実行する。見つからない (終了コード 1) ときは、明細ファイルを添付するよう頼んで止まる。
2. **チェックを実行**: `python3 scripts/expense_check.py <明細ファイル> --out violations.csv`
   - Excel で複数シートがある場合は `--sheet <シート名>`。
   - 利用者が締め日など基準日を示したら `--as-of 2026-10-31`。示さなければ実行日が基準日になる。
   - 自社ルールが添付されていれば `--rules <ルール.json>`。
3. **出力を読む**: 標準出力の Markdown に、列の対応・概要・チェック別件数・指摘一覧・適用したルールが出る。「必須列がない」が出たら、列名の対応が合っていない可能性が高い。列一覧を確かめ、利用者に正しい列を確認する。

## 回答の形
- 日本語で、まず結論 (例: 「120 行中 7 行に指摘。上限超過 3 件、重複の疑い 2 組」)。
- スクリプトの「チェック別の件数」と「指摘一覧」の表を貼る (省略行があればその旨も)。
- `violations.csv` をダウンロード用ファイルとして返す (UTF-8 BOM 付き、Excel でそのまま開ける)。
- 前提を必ず書く: 使ったファイルとシート、基準日、ルールファイル、列の対応、行番号は元ファイルの行番号であること。
- 「重複の疑い」「注意」は違反と断定しない。規程の解釈が必要な判断 (例外承認の有無など) は担当者に委ねると添える。

## エラー時
- `エラー: ...` (終了コード 2) は利用者が直せる問題。内容をそのまま伝え、対処を案内する。
- 文字コードを判定できない: Excel で「CSV UTF-8」として保存し直すか、`--encoding cp932` を試す。
- ルールファイルの JSON が不正: エラーに出た位置を示し、修正を頼む。ルールを推測で補わない。
- 列が見つからない: 表示された列一覧を見せて、どの列が日付・金額・費目・支払先かを確認する。
