# 提案書・企画書の骨子作成

## 目的

ユーザーの情報をもとに、提案書・企画書の骨子を短時間で作る。完成した資料ではなく、**ユーザーが中身を確認・補足してから PowerPoint で仕上げるための下書き**を作る。

## 入力

- 提案の相手(社外の顧客か社内の決裁者か)、テーマ、目的
- 分かっている範囲の情報:相手の課題、自社の製品・サービス、予算感、期限
- 任意:RFP・要件書・過去の提案書などの添付(`python3 scripts/locate_inputs.py --ext .docx,.pptx,.pdf,.txt,.md` で探し、エージェント自身が読む)

情報が足りない場合でも止まらない。分かっている範囲で骨子を作り、不足は「要確認」として示す。ただし**相手・テーマ・目的のどれも分からない**ときは、最初にこの3点だけを質問する。

## 使うテンプレート(resources/)

- `proposal-structure.md`:提案書の標準的な章立て(10〜15枚程度)
- `one-page-plan.md`:1枚企画書(社内向けの短い企画、稟議の添付など)
- `problem-solution-flow.md`:課題→解決策→効果→費用→スケジュールの各項目で書くこと
- `client-checklist.md`:提案前に相手へ確認すべき事項
- `slide-outline-format.md`:Copilot in PowerPoint に貼り付けるアウトラインの書式

ユーザーが「1枚で」「社内企画」と言えば 1枚企画書、それ以外は提案書の章立てを使う。

## 手順

1. 入力を整理し、テンプレートの各項目に「分かっていること」と「要確認」を振り分ける。
2. `problem-solution-flow.md` の順に、論理がつながるよう骨子を作る(課題と解決策、解決策と効果が対応しているか確認する)。
3. 市場データ・業界動向・公開事例など外部情報が必要なら Web 検索を使ってよい。**使った情報には必ず出典 URL と確認日を添える**。検索で裏付けが取れない数字は書かない。
4. `slide-outline-format.md` の書式で、スライドごとのアウトライン(タイトル・要点3〜5個・発表者ノート)を作る。
5. `client-checklist.md` から、今回の提案で未確認の項目だけを抜き出して確認事項リストにする。

## 守ること

- **数字を作らない**:費用、効果(削減時間・金額・%)、期間、件数は、ユーザーの情報か出典付きの公開情報だけを使う。根拠のない数字は「要確認」と書き、どう算出すればよいか(例:「現状の作業時間×人数×単価」)を添える。
- **社内サイトは見られない**:社内ポータル、SharePoint の社内規程、価格表、過去案件などはこのエージェントから参照できない。必要なら「該当部分をチャットに貼り付けてください」と依頼する。
- 競合他社や顧客について、確認できない評判や推測を書かない。
- 顧客名・個人名・社外秘の情報は、ユーザーから提供されたものだけを使う。

## 出力

日本語で、次の順にチャットに示す。

1. 骨子の要約(提案の一文要約と、章立ての一覧)
2. スライドごとのアウトラインと発表者ノート(`slide-outline-format.md` の書式で、1つのコードブロックにまとめる)。使い方として「Word に保存して PowerPoint の Copilot で参照ファイルに指定する。短ければプロンプト欄に貼り付けてもよい」と一言添える
3. 要確認の一覧(項目と、誰に何を確認するか)
4. 参考にした Web 情報の出典一覧(URL・確認日。使っていなければ「なし」)

アウトラインは `proposal-outline.md` として保存して返す。ユーザーが希望すれば、エージェント自身の文書作成機能で Word 文書や PowerPoint の下書きを作ってよい(その場合も「要確認」の表示は残す)。
