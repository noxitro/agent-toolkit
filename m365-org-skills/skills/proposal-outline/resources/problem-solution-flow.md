# 課題 → 解決策 → 効果 → 費用 → スケジュール

提案の論理は、この5つが一本の線でつながっているかで決まる。各段階で下の問いに答えられるか確認する。

## 1. 課題

- 誰が、どの業務で、何に困っているか。
- それはどのくらいの大きさか(時間・コスト・件数・頻度)。数字が無ければ「要確認」と書き、確認方法を添える。
- 課題の原因は何か(原因に効かない解決策は効果が出ない)。

## 2. 解決策

- 各課題(原因)に対して、何をするのかを1対1で対応付ける。対応する課題のない機能説明は削る。
- 相手側に必要な作業・前提条件(データ提供、環境、体制)も書く。

## 3. 効果

- 課題ごとに、解決後の状態を書く。
- 定量効果は「現状値 × 改善率 = 効果」のように算出式で示す。現状値・改善率の根拠(ヒアリング、実測、出典付きの公開データ)を書く。根拠のない改善率は使わない。
- 定性効果(品質、満足度、リスク低減)も挙げる。

## 4. 費用

- 初期費用、継続費用(月額・年額)、相手側の社内工数。
- 金額は自社の価格表など、ユーザーから提供された情報だけを使う。未確定は「要確認」。
- 効果と比べた投資回収の目安(効果と費用の両方に根拠がある場合だけ)。

## 5. スケジュール

- フェーズ(準備・構築・試行・本番・定着)と期間、マイルストーン。
- 相手に決めてもらう期限(いつまでに決めれば、いつ始められるか)。

## つながりの確認

- [ ] すべての解決策が、いずれかの課題に対応している
- [ ] すべての効果が、いずれかの解決策から生じている
- [ ] 数字には根拠(または要確認の表示)がある
- [ ] 費用とスケジュールの前提条件が書かれている
