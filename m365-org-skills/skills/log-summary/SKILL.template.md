# ログ集計 (log-summary)

## 目的

大量のログを機械的に数え、「どのメッセージが・いつ・何件」出たかを正確に示す。件数や時刻は必ずスクリプトの出力から取る。原因の推測を書くときは、集計結果と区別して「推測」と明記する。

## 前提

- スクリプトのサンドボックスはインターネットにも社内ネットワークにも接続できない。サーバーや監視ツールには接続できず、扱えるのは添付されたログファイルだけ。
- 対応する日時の形式: ISO 8601 (`2026-10-01T09:00:00`)、`2026/10/01 09:00:00`、syslog (`Oct  1 09:00:00`、年は今年とみなす)、Apache/Nginx (`[01/Oct/2026:09:00:00 +0900]`)。タイムゾーンの換算はしない。
- 日時のある行から次の日時のある行までを 1 件 (レコード) として数える。スタックトレースや例外メッセージなど日時のない続きの行は、直前のレコードの一部になる。
- ログに含まれる個人情報・認証情報は回答に書き写さない (例の行は必要な部分だけ示す)。

## 手順

1. **ファイルを探す**: `python3 scripts/locate_inputs.py --ext .log,.txt,.gz,.zip,.out` を実行する。見つからない (終了コード 1) ときは、ログファイルを添付するよう頼んで止まる。
2. **全体を集計**: `python3 scripts/log_summary.py <ファイル>...` (複数ファイル・.zip も可)。
3. **依頼に応じて絞り込む**:
   - エラーだけ: `--level ERROR,FATAL`
   - キーワード: `--grep "timeout|タイムアウト"` (正規表現、大文字小文字は区別しない。各レコードの先頭行が対象)
   - 期間: `--since "2026-10-01 09:00" --until "2026-10-01 12:00"`
   - 時系列の単位: `--bucket hour` / `--bucket day` (既定は期間 3 日以内なら時間単位)
   - syslog の年を指定されたら `--year 2025`
4. **出力を読む**: 標準出力の Markdown に、レベル別件数・頻出メッセージ・時間帯別件数・ファイル別件数が出る。「注意:」行は回答に含める。

## 回答の形

- 日本語で、まず結論 (例: 「ERROR 152 件。最多は DB 接続タイムアウト 98 件で、10/1 9 時台に集中」)。
- スクリプトの表 (レベル別、頻出メッセージ、時間帯別) を貼る。長い場合は上位と山場に絞り、省略したことを書く。
- `log_summary_templates.csv` (全パターン) と `log_summary_timeline.csv` (時系列) をダウンロード用ファイルとして返す。
- 前提を書く: 対象ファイル、期間、絞り込み条件、syslog の年の仮定、`<N>` `<IP>` `<PATH>` などは値を伏せて同じ種類のメッセージをまとめた印であること。

## エラー時

- `エラー: ...` (終了コード 2) は利用者が直せる問題。内容をそのまま伝え、対処を案内する。
- 正規表現が不正: 正しい書き方に直して再実行する。
- ログが大きすぎる (合計 512 MB 超): 期間やファイルを絞って添付してもらう。
- 日時を 1 つも検出できない場合は 1 行ずつ数えた結果になる。時間帯別の集計はできないと伝える。
