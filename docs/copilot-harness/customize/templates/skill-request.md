# スキル依頼票 — `{{skill-name}}`

> **使い方**: スキルを 1 本作るたびにこの票を 1 枚コピーして埋める(置き場: スキルと同じディレクトリの
> `.github/skills/{{skill-name}}/REQUEST.md`)。この票は Copilot チャットに
> 「この票のとおりに SKILL.md を書いて」と渡す入力であり、同時に段 4(レビュー)で照合する
> 受け入れ基準でもある。票に無い要件はスキルに入れない。

| 項目 | 記入 |
| --- | --- |
| スキル名(`name`) | `{{skill-name}}`(小文字・数字・ハイフンのみ、64 字以内、ディレクトリ名と一致) |
| 置き場 | `.github/skills/{{skill-name}}/`(チームで使うものはリポジトリに置く。個人用の置き場に置かない) |
| 依頼者 / 日付 | {{名前}} / {{YYYY-MM-DD}} |
| 種別 | 手順型(決まった作業を再現) ・ 知識型(判断基準や仕様を供給) ・ 検査型(成果物を機械的に確認) ・ 起動型(定型の起動文。`/{{skill-name}}` で呼ぶ) |
| 使う面 | Copilot CLI(およびそれを基盤とする面)。他の面や他のエージェント環境で使うなら追記 |

## 1. 発動させたい場面(description の素材)

description は「何が書いてあるか」ではなく「いつ使うか」を書く。ここに場面を 2〜4 個、
ユーザーが実際に打ちそうな言い回しで列挙する。これがそのまま段 3(発動試験)の陽性ケースになる。

- 「{{例: テスト用のフィクスチャデータを 100 件生成して}}」
- 「{{例: このスキーマに合うサンプルデータを作って}}」
- 「{{...}}」

**発動させたくない場面(陰性ケース)**: 似ているが対象外の依頼を 1〜2 個。

- 「{{例: ログの保存形式を変換して}}」→ 対象が違うので別スキル
- 「{{例: 設定ファイルの仕様を説明して}}」→ 変換はしないので発動不要

## 2. スキルが知っているべきこと

Copilot が素のままでは知らない、このプロジェクト固有の事実。出典(ファイルパス・文書名)付きで。
外部 API(SDK・ライブラリ)に関する事実は、**インストール済みの版**と文書・ヘッダの場所を書く。
版の無い事実は受け入れない(段 4 で差し戻し)。

| 事実 | 出典(版) |
| --- | --- |
| {{例: 設定ファイルの先頭行は形式名とバージョンのヘッダ}} | {{例: `docs/config-format.md`}} |
| {{例: 変換 API の `flags` 引数の既定値は版 X.Y で変わった}} | {{例: SDK X.Y.Z `include/convert.h:120`}} |
| {{...}} | {{...}} |

## 3. 手順(手順型・検査型・起動型のみ)

スキル本文に書く手順の骨子。「意図と品質基準」を書き、細かな操作はエージェントに任せる。
「止めて報告する」条件を 1 つ以上入れる。

1. {{例: 入力ファイルのヘッダを確認し、未対応バージョンなら止まって報告する}}
2. {{例: `tools/convert-config` を実行し、出力を `fixtures/expected/` と比較する}}
3. {{例: 差分があれば原因候補を列挙して止まる。黙って上書きしない}}

## 4. 同梱ファイル

SKILL.md と同じディレクトリに置く補助ファイル。無ければ「なし」。

| パス(相対) | 内容 |
| --- | --- |
| `references/{{...}}.md` | {{長い仕様など。SKILL.md 本文は 500 行以内に収める}} |
| `scripts/{{...}}` | {{実行補助。実行前提のツールがあれば本文に明記}} |

## 5. 受け入れ基準(段 2〜4 で照合)

- [ ] frontmatter: `name` がディレクトリ名と一致、`description` が 1024 字以内で「いつ使うか」になっている
- [ ] 発動試験: 上の陽性ケースで発動し、陰性ケースで発動しない(結果は `TEST_LOG.md` に残す)。使う面ごとに試す
- [ ] 本文に Copilot が解釈しない他のエージェント環境固有のキーが無い(`allowed-tools` は Copilot でも有効だが、shell 系の事前承認は入れない)
- [ ] 本文に機種依存の絶対パス(ドライブレター付きのパスなど)が無い
- [ ] 同梱ファイルは相対パスで参照されている
- [ ] 第 2 節の外部 API に関する事実に、版と文書・ヘッダの場所が付いている
- [ ] 本文に「テストコードを変えない」「止めて報告する条件」が入っている(手順型・起動型)
- [ ] {{プロジェクト固有の基準があれば追記}}
