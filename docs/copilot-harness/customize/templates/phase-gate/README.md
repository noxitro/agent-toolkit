# phase-gate — フェーズゲートの 1 周をワークフローで回す

[phase-loop](../phase-loop/SKILL.md) と同じ段取りを、GitHub Copilot の dynamic workflows のコードで固定したもの。
1 回の実行で、HARNESS.md のフェーズを 1 つ回す。

```text
準備 → 実装役(implementer) → 審査前の差分を採取 → 審査役(reviewer) → 審査後の差分を採取して比べる
     → FAIL なら再現手順付きで差し戻し(最大 3 周) → 締め(人が確かめる) → 記録案(phase-log.csv・TEST_REPORT.md)
```

phase-loop との違い:

| | phase-loop(スキル) | phase-gate(ワークフロー) |
| --- | --- | --- |
| 段取りの書き方 | 指示文。モデルが読んで従う | コード。周回の数え方・止まる所・差分の比較をコードが行う |
| 段取りを飛ばす余地 | ある(モデル次第) | 無い |
| 人が判断する所 | オーケストレータが人に聞く | チェックポイントで一時停止し、人が再開する |
| 機能の状態 | スキルは一般提供 | dynamic workflows はプレビュー。仕様が変わりうる |

## 前提

- ルートに `HARNESS.md`(フェーズの見出しが `### Phase N: …`)。
- `.github/agents/implementer.agent.md` と `.github/agents/reviewer.agent.md`(この雛形の定型報告と VERDICT を返すもの)。
- `docs/TEST_REPORT.md`(結果マトリクスの見出しに「環境 A」「レビュー周回数」「審査前後の差分一致」の列がある。列の数と順番は問わない)。
- 証拠の置き場 `e2e-artifacts/` を `.gitignore` に入れる。

## 置き方

1. [extension.mjs](extension.mjs) を `.github/extensions/phase-gate/extension.mjs` にコピーする。
2. 必要なら、ファイルの先頭の定数だけを直す(下の表)。段取りは変えない。
3. 使えることを確かめる。新しいセッションで「使えるワークフローを一覧して」と送り、`phase-gate` が出ればよい。
   - Copilot CLI では `--experimental` を付けて起動するか、`/experimental on` を実行する。CLI を基盤とする面には、設定なしで使えるものもある。
   - プロジェクトの拡張は、信頼したフォルダでだけ読まれる。組織から Copilot を受けている場合は、Copilot CLI のポリシーが有効であること。

| 定数 | 既定 | 意味 |
| --- | --- | --- |
| `MAX_ROUNDS` | 3 | 審査の差し戻しの上限。超えたら止まり、次の周回は始めない |
| `MAX_FORMAT_RETRIES` | 2 | 実装役の報告が定型にならないときの出し直しの回数 |
| `ART` | `e2e-artifacts` | 証拠の置き場。HARNESS.md の「証拠の置き場」と同じにする |
| `READ_ALSO` | `["GOAL.md"]` | HARNESS.md と一緒に実装役へ読ませる文書(ルートにあるものだけ) |
| `PROTECTED` | `[]` | 触ってはいけないファイルの正規表現。締めで変更の有無を見せる |
| `HEDGE` | おそらく・たぶん・はず | この語を含む PASS は数えず、再審査する |

## 回し方

1. 新しいセッション(モードは対話)で、次のように頼む。

   > ワークフロー phase-gate を Phase 1 で開始してください(引数 `{"phase": 1}`)

2. チェックポイントで一時停止したら、中身(`e2e-artifacts/phase-N-checkpoint-<key>.md`)を読む。
   人の判断を渡すときは `e2e-artifacts/phase-N-human-note-<key>.md` に書く(任意。次の実装の依頼に「人の指示」として入る)。
3. 次のように頼んで再開する。`<run ID>` は一時停止したときに出る。

   > 一時停止しているワークフロー phase-gate の run <run ID> を再開して、結果を見せて。

4. 締め(`closing`)で止まったら、このフェーズで人が介入した時間(分)を、数字だけで `e2e-artifacts/phase-N-human-minutes.txt` に書いてから再開する。
5. 終わると、`docs/phase-log.csv` の追記案と `docs/TEST_REPORT.md` の更新案が `e2e-artifacts/` に差分として出る。適用とコミットは人が行う(ワークフローはコミットしない)。

| チェックポイント | 止まる理由 | 人がすること |
| --- | --- | --- |
| `impl-null-N` | 実装役が結果を返さなかった | AI クレジットの枠・上限・接続をセッションのログで確かめ、解消してから再開する |
| `impl-format-N` | 出し直しても報告が定型にならない | 実装役の定義と報告を見直し、判断を note に書いて再開する |
| `impl-stopped-N` | 実装役が「止めて報告」した | 判断を note に書いて再開する |
| `review-null-…` | 審査役が結果を返さなかった | 原因を解消してから再開する(再審査する) |
| `diff-changed-…` | 審査の前後で作業ツリーが変わった | 変わった物を確かめて戻し、再開する(その判定は無効で、再審査する) |
| `hedge-…` | PASS に推測の語がある | 再開する(再審査する) |
| `fail-no-items-N` | FAIL なのに修正項目が無い | 判断を note に書いて再開する |
| `max-rounds` | 上限の周回で PASS しなかった | フェーズの分割か要件の見直しを決める |
| `closing` | PASS。差分と審査結果の突き合わせ | 報告に無い変更ファイルを確かめ、介入時間を書いて再開する |
| `minutes` | 介入時間が書かれていない | 書いて再開する(書かなければ「未記入」で記録する) |

## 費用とモデル

- 実装役と審査役のモデルは、エージェントの定義の `model:` で決まる。省略すれば本体と同じ。記録案のモデル名も定義から読む。
- ワークフローが起こすエージェントは 1 回の実行で合計 12 まで、同時に 1 つ。AI クレジットの上限は付けていない。費用はセッションの上限や、計画の予算で止める。
- サブエージェントの失敗(AI クレジットの枠切れを含む)は、例外にならずに空の結果で返る。phase-gate はそれを `impl-null` / `review-null` で止める。
- 本体を自分の API キー(BYOK)で動かしても、ワークフローのサブエージェントは Copilot 側のモデルで動き、AI クレジットを使うことがある。費用はサブエージェントの分も見る。

## テスト

`node --test`(このフォルダか、リポジトリのルートで)。AI クレジットを使わない。
SDK の決まりに合わせた偽の実行環境で、隣の雛形(HARNESS.md・TEST_REPORT.md・エージェントの定義)から試験用のリポジトリを作り、
1 周目の PASS、差し戻し、周回の上限、止めて報告、空の結果、報告の出し直し、審査前後の差分の不一致、推測の語、Phase 0 と CRLF を確かめる。

テストが見るのは段取りの分岐だけ。実際のモデルでの振る舞い(報告の形、審査の質)は、置いた後に、
[HARNESS.md](../HARNESS.md) の付録 B の陰性コントロールと陽性コントロールで確かめる
(Phase 0 が PASS まで通ること、壊した実装で FAIL が出て、指摘がその箇所を指すこと)。
