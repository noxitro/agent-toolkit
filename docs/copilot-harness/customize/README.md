# カスタマイズとユーザーハーネス

導入編(GitHub Copilot app の導入、文脈・トークン・worktree の概念、モデル、コードの修正とバグ修正の実演)を
終えた人向けの資料。エージェント環境に**決まった振る舞いをさせる 4 つの部品**(指示・スキル・カスタムエージェント・MCP)と、
それらを組み合わせて「実装役が作る → 審査役が検証する → ゲートを満たしたら次へ」を回す**ユーザーハーネス**を扱う。
読み終えたら、自分のリポジトリでユーザーハーネスを 1 周回せる状態になることが到達目標。

スライド版: [slides/customize-guide.pptx](slides/customize-guide.pptx)(本資料の要点を 1 章 3〜6 枚に圧縮したもの。説明会用。本文が正)。

## この資料の方針

- **デファクトスタンダードで説明する。** 置き場・書式・呼び方は GitHub Copilot(CLI とアプリ)のものを示す。
  他のエージェント環境(Claude Code、OpenCode、Codex など)での登録方法は説明しない。付録 E に対応の有無だけ載せる。
- **載せる機能の基準は 1 つ。** GitHub Copilot(CLI・アプリ)で対応し、**かつ**他のエージェント環境のどれか 1 つ以上で
  同じ形式か同じ考え方が通用するもの。特定の 1 環境だけが非対応でも問題にしない。この基準で落ちたもの(プロンプトファイルなど)は
  付録 D に名前と理由だけ載せる。
- **すぐ廃れるものを書かない。** モデル名・価格・画面の細部・言い回しのテクニックは書かない。版で変わるものには時点(2026-10)を付け、
  保証ではなくスナップショットとして読む。

## 用語

| 語 | この資料での意味 |
| --- | --- |
| **エージェント環境** | コードを読み書きし、コマンドを実行するエージェントの実行環境。導入編で推奨した GitHub Copilot app(Copilot CLI の上に構築されている ◎)が既定。Claude Code、OpenCode、Codex も同じ層 |
| **ユーザーハーネス** | 利用者が自分で組む運用の仕組み。実装役と審査役のカスタムエージェント、フェーズ定義とゲート条件を書いた HARNESS.md、1 周を固定する起動スキル、結果の置き場で構成する(第 5 章)。世間で「ハーネス」と呼ばれる実行環境そのものとは別の意味で使う |
| **文脈(コンテキスト)** | モデルが 1 回の応答で読める入力の全体。指示・スキルの description・MCP のツール定義は常時ここに乗る(導入編の「コンテキスト」と同じ) |
| **面** | 同じ Copilot を使う窓口の違い(アプリ、CLI、VS Code、Visual Studio)。本資料はアプリと CLI を前提にする |
| **フェーズ / ゲート条件** | 作業を区切る単位と、審査役が機械的に確認できる合格条件 |

確度の表記: **◎** 公式文書で確認(取得日 2026-10-21、付録 G に文書名と URL)/ **△** 実測、または単一事例 / **▲** 推測(裏付けなし。手元の環境で確かめてから信じる)。

## 章立て

各章は「仕組み → Copilot での置き場と登録 → 設計の原則 → 目で確認する → 落とし穴」の順で書いてある。
第 1〜4 章は部品、第 5 章がそれらを組み合わせる到達点。

| 章 | 内容 | 目安 |
| --- | --- | --- |
| [1. 指示ファイル](01-instructions.md) | 常時読まれる前提の置き方。層と優先、前提と手順の切り分け、正典を 1 か所にする | 30 分 |
| [2. スキル](02-skills.md) | Agent Skills 標準。description が発動を決める仕組み、登録、作り方の 5 段、増やしすぎない | 60 分 |
| [3. カスタムエージェント](03-agents.md) | 役割を固定した定義。選択と委譲、読み取り専用の審査役、委譲のコスト | 60 分 |
| [4. MCP](04-mcp.md) | 外部ツールへの接続。設定と権限、「CLI があるなら MCP にしない」判断 | 45 分 |
| [5. ユーザーハーネス](05-user-harness.md) | 部品を組み合わせて 1 周回す。HARNESS.md をエージェントと相談して書く手順、陽性コントロール、共有の仕方 | 120 分 |
| [6. 付録](06-appendix.md) | 判定一覧、置き場早見表、確認コマンド集、対象外の機能、他環境の対応表、スクリーンショットの撮影指定、参照 URL、用語集 | — |
| [templates/](templates/HARNESS.md) | 第 5 章の雛形(HARNESS.md、実装役・審査役、phase-loop スキル、TEST_REPORT.md、SKILL.md、依頼票) | — |

## 前提(導入編で済んでいること)

- GitHub Copilot appがインストールされ、サインインできている
- リポジトリをローカルに clone し、**リポジトリのルート**でセッションを開ける(別の場所で開くと `.github/` の資産が見えない)
- ビルドとテストが**各 1 行のコマンド**で動く(例: `cmake --build build` と `ctest --test-dir build`)。1 行で動かないと第 5 章の審査役が測り直せない
- 文脈・トークン・worktree の意味を知っている

## この資料で扱わないもの

- 他のエージェント環境での登録手順(付録 E に対応の有無だけ)
- 基準で落ちた機能の操作(付録 D)。フックとプラグインは仕組みの概要だけ付録に置く
- モデルの選び方と価格(別紙。本資料は「測り方」だけ第 3 章に書く)
- VS Code / Visual Studio 固有の設定

## スクリーンショットについて

本文中の `📷 SS-n` は、説明会の前にリーダーが手元の環境で撮って差し込む位置。アプリの画面は版で変わるため、資料には固定の画像を入れていない。
何を撮るかの一覧と撮影時の注意は[付録 F](06-appendix.md#f-スクリーンショットの撮影指定)。
