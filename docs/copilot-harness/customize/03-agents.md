# 3. カスタムエージェント — 役割を決めた助っ人

## これは何

「レビュー担当」「実装担当」のように、**役割・守ること・使える道具**を決めたエージェントです。
自分で選んで話しかけることも、いつものエージェントに「レビュー担当に確認させて」と仕事を任せることもできます。
任された側は別の会話で動くので、いつもの会話が散らかりません。

## 置き場

`.github/agents/<名前>.agent.md`(例: `.github/agents/reviewer.agent.md`)

## 例: コードを直さないレビュー担当

```markdown
---
name: reviewer
description: 変更を確かめて、合格か不合格かを証拠付きで返すレビュー担当。コードは直さない。
tools: ["read", "search", "execute"]
---

あなたはレビュー担当です。

- コードを直さない。直したくなったら「不合格」として理由を書く。
- 実装した人の「動きました」を信じず、自分でビルドとテストを実行して結果を貼る。
- 最後に「合格」か「不合格」を 1 行で書く。
```

`tools` は使える道具の一覧です。読む(`read`)・探す(`search`)・コマンドを実行する(`execute`)だけを渡し、
書き換える道具(`edit`)を渡していないので、このエージェントはファイルを直せません。

## 使い方

- `/agent` と打って一覧から選ぶ。
- または、依頼の中で名前を出す(「reviewer に確認させて」)。

## 作り方: エージェントに頼む

```text
コードを直さずに確認だけするレビュー担当のカスタムエージェントを .github/agents/reviewer.agent.md に作って。
自分でビルドとテストを実行して確かめ、最後に合格か不合格かを書く役にして。
```

## 効いているか確かめる

- `/agent` の一覧に出るか。
- reviewer を選んで「このファイルの 1 行を直して」と頼み、**直さずに断るか**。

## コツは 3 つ

- **役割は 1 つに絞る。**
- **確かめる役には、書き換える道具を渡さない。**
- **何でも分けない。** 普段の作業はいつものエージェントで十分です。分けるほど時間とコストが増えます。

## 育て方

レビュー担当が見落としたことがあれば、「〜も確認する」を 1 行足します。
